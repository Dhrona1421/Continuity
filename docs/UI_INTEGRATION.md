# Incident-detail integration (Part 4)

`frontend/src/App.jsx` keeps the five existing incident tabs and mounts `IncidentMemory` **below** the selected tab content. On incident selection it automatically calls `POST /api/v1/memory/recall` and `POST /api/v1/incidents/{id}/recommendation` through the same-origin helper (`frontend/src/api.js`). Security Memory shows each provider-confirmed historical incident's successful paths/actions (or explicitly **analyst-reported** accepted outcomes), failed paths/actions, side effects, lessons and analyst decisions, or an explicit no-history/unavailable state. It separately reads `GET /api/v1/incidents/{id}/experience` to show the **current case's** source-authored outcome, failure, side effects and lesson—labeled as current-case data, never as recalled history. This lets the first NovaBank case show its reported exercise failure even though it has no prior memory. AI Recommendation shows ordered steps, confidence, a current-only comparison toggle that requests a *real* new inference, expandable reasoning, source incident IDs and conflict explanation. It shows explicit inference errors without blocking the original investigation.

Analyst chooses Accept/Modify/Reject, supplies a reason (and modification if relevant), optionally records an observed outcome and an explicit conditional lesson, then presses **Save Learning**. Previously saved decisions/outcomes are displayed from the current incident's persisted experience. This posts to `/api/v1/memory/learn` with the persisted recommendation ID; backend checks ID belongs to this incident, records analyst identity and decision, and re-retains/upserts the Hindsight document. If Hindsight is down, the panel says the decision is only locally recorded and must be retried; it does not pretend the loop closed. Recalling after success can affect a *different* incident's recommendation. An accepted recommendation does not mean containment succeeded. No new response execution control exists in this component: actions are still requested only via the existing `ResponseConsole` in Response & audit, with server-side policy/approval and audit unchanged.

`npm run lint` and `npm run build` validate the frontend compilation. Chromium/Playwright browser checks were run for the unconfigured local API (explicit unavailable states, current incident's reported failure and lesson) and an isolated real HTTP stack backed by **deterministic provider test doubles** (NovaBank 1→2→3, memory bypass, feedback and conditional lesson, two source citations/conflict, no AI-triggered response action). A separate mobile viewport check found no horizontal overflow. This validates UI interactions against the tested contracts; a **live Hindsight and inference provider** browser E2E still requires running services/credentials and was not possible here. Do not mistake deterministic provider output for real-model reasoning or measured investigation improvement.
# Continuity interface notes

The application includes a first-class **Security Memory** page. Its search calls `POST /api/v1/memory/search` and displays facts Hindsight actually recalled, including World Facts that are not linked to a local source record. It attaches a source incident only when the Hindsight document ID matches a retained GhostSOC record. Incident recommendations use only provenance-matched historical experiences; current-case data, Hindsight history, Groq recommendations, analyst decisions, and response actions remain in separate sections.
