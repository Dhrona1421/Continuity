# Investigation recommendation agent (Part 3)

`POST /api/v1/incidents/{id}/recommendation` requires `RUN_INVESTIGATION` and does **not** import or invoke response execution. `backend/app/services/agent.py` builds a bounded current-incident snapshot (risk, reasons, techniques, alerts, IOCs, evidence/timeline) and asks Hindsight to recall source-documented experiences. It sends both as **untrusted context** to the configured OpenAI-compatible Groq endpoint (`GHOSTSOC_LLM_BASE_URL=https://api.groq.com/openai/v1`, `_API_KEY`, `_MODEL=openai/gpt-oss-120b`, `_TIMEOUT_SECONDS`). The adapter uses chat completions with JSON output; Groq is the reasoning provider, while Hindsight is the memory provider. It requests ordered steps, plain-language reasoning, next steps, confidence, cited incident IDs and conflict reasoning. The exact prompt is in the service. There is **no** hardcoded AI answer when inference is unconfigured/unavailable: `status=unavailable` keeps investigation usable.

The provider cannot create historical citations: the server projects `historical_evidence` only from Hindsight-returned document IDs whose structured source rows are retained. An unknown cited incident ID or UUID in displayed recommendation text fails closed. When Hindsight is available but has no relevant matches, the output includes the literal `No relevant historical experience found.` and no historical citations. A provider outage is instead labeled `Security Memory unavailable; recommendation uses current evidence only.`; the explicit without-memory comparison is labeled as bypassed. Neither situation is misrepresented as a successful empty recall. Detected success-versus-failure/rejection trade-offs require explicit conflict reasoning; errors/invalid JSON or provider timeouts become `unavailable`. A provider may still produce misleading natural-language reasoning without an unrecognized ID; human review is required and fact checking of free text is not mathematically guaranteed. Recommendations are persisted with IDs so analyst feedback can be tied to the incident. `without_memory=true` requests a current-only contrast while still using the actual inference provider; it never simulates an AI answer.

Failure, success, rejection and conflicting memory all enter the prompt as separate structured signals, with lessons, side effects and provider-returned fact text. Thus a *real configured* model can change the proposed sequence; the service never takes an action. An agent suggestion like disabling an account must remain a human escalation, because GhostSOC does not implement that typed action. To act, an analyst must use existing `ResponseConsole` → policy → approval → dry-run/verified adapter → audit. Never interpret a simulated response as containment.

**Evaluation status (2026-09-28):** `backend/tests/test_agent_contract.py` uses explicit stubs and is not counted as live-provider proof. A separate seven-case run against the configured Hindsight Cloud bank and Groq (`openai/gpt-oss-120b`) passed 7/7 checks over the three labeled synthetic NovaBank incidents. Six recommendation calls had a median latency of 4.14 s and a maximum of 5.69 s in that run. It verified relevant recall, the no-memory path, failure-aware ordering, retained/recalled analyst feedback, rejection learning, conflict explanation, and a changed later recommendation. These are functional checks on one synthetic scenario, not production accuracy, time-saved, or acceptance metrics. Groq is the reasoning provider used by this submission. The provider path now has one bounded retry for transient transport/429/5xx failures and one constrained correction attempt for provenance/conflict validation errors; it still fails closed after those limits.
